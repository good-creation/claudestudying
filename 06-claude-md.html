0:02動機

毎回ゼロから始めさせないために

CLAUDE.md がない状態で Claude Code を開くと、毎回まっさらから始めることになる。そこで発生するのが3つの再発見コスト。

  • コードベースを探索し直す
  • 必要な依存関係を理解し直す
  • 実装済みの機能を把握し直す

そして最後に、いちばん厄介なものが加わる——ときには推測をしなければならない。それが、Claude を正しい方向に導くことを難しくする。

確認 CLAUDE.md が無い状態で毎回発生する再発見コストに含まれないのはどれか。
  • 必要な依存関係を理解し直す
  • コードベースを探索し直す
  • コミットメッセージのスタイルを統一し直す

答え: C — 挙げられているのはコードベースの探索・依存関係の理解・実装済み機能の把握の3つと、推測の必要性。

コミットメッセージのスタイル統一は、この節では触れられていない。

0:52中身

何を書くのか

以下のファイル内容が、そのまま手本になる。

  • スタック

    「これは App Router、Tailwind、Drizzle ORM を使った Next.js 15 のアプリ」——1行で全体像。

  • コマンド

    開発サーバー、テスト実行、Lint。プロジェクト固有の呼び出し方を書いておく。

  • コードスタイル

    インデントは2スペース、名前付きエクスポートを好む。

  • プロジェクトの決めごと

    API ルートはすべて app/api に置く、可能な限り API ルートではなく Server Actions を使う。

効果もはっきり述べられる。この状態で React コンポーネントの作成を頼めば、Claude は最初から Tailwind（あるいはあなたが使っている CSS フレームワーク）でスタイルを当てる方法を知っている。まず全体を理解しにいく手間がない分、初手から仕事が良くなる。

確認 CLAUDE.md に書く内容として、本文の実例が挙げていないのはどれか。
  • 使っているスタック（フレームワークや ORM）の1行紹介
  • 開発サーバーやテストのプロジェクト固有の呼び出し方
  • チームメンバー個人のエディタのキーボードショートカット設定

答え: C — 実例が挙げるのはスタック・コマンド・コードスタイル・プロジェクトの決めごとの4項目。

個人のエディタ設定のような話は登場せず、「他の人にも当てはまるか」という観点からもプロジェクト全体向けの内容にとどまる。

1:31階層

チームのためのファイル

CLAUDE.md はバージョン管理にコミットできる（し、そうすべき）。チーム全体がその恩恵を受けられる。ただし、誰のためのものかによってメモリファイルには階層がある。

「他の人にも当てはまるか」だけで決まる。プロジェクトの事実はプロジェクトへ、あなたの癖はユーザーへ。ここを混ぜると、チームの誰かにとって邪魔なルールが共有ファイルに紛れ込む。

確認 「コメントの書き方」のような個人的な好みは、どちらのレベルのメモリファイルに書くべきか。
  • どちらにも書かず、プロンプトで毎回伝える
  • プロジェクトレベル（バージョン管理にコミット）
  • ユーザーレベル（設定フォルダ・全プロジェクトに適用）

答え: C — 個人的な好みはユーザーレベルに書く。切り分けの基準は「他の人にも当てはまるか」の一点。

プロジェクトレベルはチームで共有されるため、個人の癖を混ぜるとチームの誰かにとって邪魔なルールになってしまう。

2:00ヒント

運用の3つのヒント

01 — Save to memory

修正内容をメモリに保存する

Claude に同じ修正を繰り返しているなら——たとえば「API ルートではなく常に Server Actions を使え」と毎回言っているなら——そのルールをメモリに保存するよう明示的に頼む。次にプロジェクトを開いたときには把握している。

02 — @ reference

ドキュメントを参照させる

参照してほしいドキュメントがプロジェクト内にあるなら、@ 記号とファイルパスを使う。中身を丸ごと転記せずに、必要なときだけ読ませられる。

03 — Start empty

最初は無しで始める

プロジェクトの開始時はあえて CLAUDE.md 無しで始めることが推奨される。そうすると、どこで常に軌道修正が必要になるかが見えてくる。これがファイルをコンパクトに、必要な情報だけに保つ方法。準備ができたら /init。

@ 参照の書き方

## README.md

Please read if you need more info: @README.md

確認 プロジェクトの開始時に、あえて CLAUDE.md 無しで始めることが推奨されるのはなぜか。
  • どこで常に軌道修正が必要になるかが見えてきて、ファイルをコンパクトに保てるから
  • ファイルを後から作ると読み込み速度が上がるから
  • /init コマンドは後からしか使えないから

答え: A — 無しで始めることで、どこで常に軌道修正が必要になるかが見えてきて、ファイルを必要な情報だけにコンパクトに保てる。

準備ができた段階で /init を使えばよく、最初から埋めにいく必要はない。
