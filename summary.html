DO能力

できること 8分類

機能名ではなくあなたが何をさせたいかで並べたもの。右端はそれを扱ったレッスン。

  • 読む — コードベースを理解する01 / 07

    「この機能を説明して」「このバグをコード全体で追跡して」。コピペで渡す必要はなく、ファイルとコードベース全体に直接アクセスする。調べるだけなら explore サブエージェントに投げるとメインのコンテキストが汚れない。

  • 書く — ファイルを編集する01

    1ファイル単位ではなく、関数のリファクタとその参照元すべての更新まで。変更の波及範囲を担当する。

  • 実行する — コマンドを走らせる01 / 02

    ビルド、テスト、パッケージのインストール。重要なのは実行して終わりではない点で、出力を見て次に何をするかを自分で決める。これがエージェンティックループの実体。

  • 調べる — Web を検索する01

    最新の API リファレンスやドキュメントが必要なら自分で取りに行く。学習データのカットオフを外部で埋める。

  • 計画する — コードを書く前に設計する03 / 04

    プランモードではファイルを編集できない。読み取り専用ツールだけで調査し、質問を返し、実行可能な詳細プランを出す。軌道修正に最適な場所は、コードが書かれる前。

  • 憶えさせる — 永続的な記憶を持たせる05 / 06

    CLAUDE.md に書けば毎セッション自動で読まれる。内容はプロンプトに追記されるので短く保つ。プロジェクト用とユーザー用の2階層。

  • 拡張する — 知識・接続・並列を足す07 / 08 / 09

    スキル＝専門知識をオンデマンドで。MCP＝外部サービスに接続。サブエージェント＝独立したコンテキストで探索させ、答えだけ返させる。

  • 強制する — 必ず起きることを保証する10

    フックだけがモデルの判断を経由しない。自動フォーマット、ログ記録、危険な操作のブロック。「毎回必ず実行される必要があるなら、プロンプトではなくフックに入れる」。

この8つを支える3つの前提

① コンテキストは有限 — 全部読ませるのではなく戦略的に探させる。② デフォルトで許可を求める — 実行と変更の前に必ず止まる。③ 間違えることがある — 意図の誤解、新しいバグ、過剰設計。状況を把握し続けることで早期に発見できる。

START導入

はじめ方

全部を一度に入れる必要はない。権限とコンテキストは、後から広げるほうが安全。

  1. ターミナルで claude を起動して普通に話しかける

    特別な構文はない。デフォルトは手動モードなので、実行・変更の前に必ず止まる。

  2. しばらく CLAUDE.md 無しで使う

    どこで毎回軌道修正しているかが見えてくる。それが書くべき内容。準備できたら /init。

  3. 複数ステップの依頼はプランモードから始める

    Shift+Tab。コードが書かれる前に計画を直す。

  4. 探索 → 計画 → コード → コミット を回す

    コミット前にサブエージェントのレビュアーを挟む。

  5. 繰り返す説明をスキルに、必ず守らせたいことをフックに移す

    お願いから保証へ。

  6. MCP は読み取り用途から試す

    使わないサーバーは /mcp で無効化する。

読むところから始めて、触らせる範囲を後から広げる。順番を逆にしない。
