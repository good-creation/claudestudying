STACK要点

5つの構成要素

組み合わせは大きく2層に分かれる。Claude Code に Cloudflare を触らせる仕組み（MCP Server / Code Mode / Skills）と、AI の使われ方そのものを管理する仕組み（AI Gateway / Access）。

01 — Connect

Cloudflare MCP Server

Claude Code を Cloudflare の外部機能につなぐ仕組み。Workers、DNS、R2、D1、ログ、分析、監査ログなどを Claude Code が参照・操作できるようになる。

02 — Context

Code Mode

Cloudflare API は非常に多いため、必要な API をその都度検索して実行する設計。Claude Code のコンテキスト消費を抑えつつ、広範な Cloudflare 機能を扱える。

03 — Knowledge

Cloudflare Skills

Claude Code に Workers、Wrangler、D1、R2、KV など Cloudflare 向け開発の知識を与える。一般的なコードではなく、Cloudflare 環境に適した実装を提案させやすくなる。

04 — Govern

AI Gateway

Claude Code、Codex、GitHub Copilot などの AI 利用をゲートウェイ経由にし、利用量・コスト・プロンプト／応答ログ・エラー・異常な利用を一元管理できる。
※ Max Plan の通信をそのまま経由させる用途とは別物 →

05 — Identity

Cloudflare Access

組織の認証と組み合わせ、誰がどの AI エージェントを使ったかを追跡・制御できる。チーム利用での費用管理や監査に有用。

コース本編との対応

01 と 02 は 09 MCP そのもの。とくに Code Mode は、あのレッスンで扱った「MCP サーバーは使っていなくてもツール定義がコンテキストを食う」という問題への回答になっている。03 は 08 スキルの「専門知識を特定タスクに」の実例。

この形なら、Claude Code は「コードを書く人」だけでなく、Cloudflare の公式ドキュメントを参照し、環境設定を確認し、ログからエラー原因を調べる開発エージェントとして機能する。

Cloudflare の MCP は2系統が提供されている——広範な Cloudflare API をカバーする Code Mode と、ドキュメント・監視・DNS 分析などに絞った専用サーバー。用途が限られているなら後者のほうがコンテキストを食わない。

SETUP導入

まず行う設定

Claude Code のプロジェクトルートで、Cloudflare 公式プラグインを導入する。

bash

claude plugin marketplace add cloudflare/skills
claude plugin install cloudflare@cloudflare

これで Cloudflare Skills が入り、Cloudflare MCP サーバーも登録される。最初に Cloudflare の機能を呼んだとき、ブラウザで OAuth 認可が始まる。認可後、次で MCP 接続を確認できる。

bash

claude mcp list

起動ディレクトリに注意

Cloudflare の wrangler.jsonc が既にあるプロジェクトでは、そのファイルがあるディレクトリから Claude Code を起動するのが推奨されている。

BUILD実装

最初に作るとよいもの

テキストと添付ファイルを貯めていく用途は、この構成の練習題材として相性がいい。規模が小さいわりに、Workers・Pages・D1・R2・ログの5つを一通り触れる。

  • ノート管理

    本文、タグ、メモ、更新日などの構造化データを D1 へ保存。

  • 資料管理

    PDF や画像を R2 に保存。

  • 検索・タグ付け API

    Workers で実装。

  • Web 画面

    Pages で公開。

  • 障害調査

    Claude Code が Cloudflare のログを確認。

Claude Code への最初の依頼例

Cloudflare Workers でノート管理アプリを作りたい。
フロントエンドは Pages、API は Workers、データは D1、PDF などの添付は R2 を使う。

まず、構成案、wrangler.jsonc、D1 のスキーマ、ローカル開発手順を提案して。
本番環境への変更・デプロイは私の確認後に行って。

この依頼なら、いきなり本番を操作させず、まず設計とローカル環境を固められる。

COST費用

重要な区別

AI Gateway の位置づけ

AI Gateway は、Claude Code Max Plan の通信をそのまま経由させる用途とは別物。AI Gateway を使う場合は、通常 Anthropic API キーなどで API を呼び出す構成になり、Max Plan の利用枠とは別に API 課金が発生し得る。Cloudflare の公式手順でも、AI Gateway 連携では Gateway の Anthropic エンドポイントと認証トークンを Claude Code に設定する。

したがって、上の 要点 04（AI Gateway）にある「利用量・コストの一元管理」は、API 課金でチームが AI を使う構成に切り替えたうえでの話と読むのが正確。Max Plan の定額利用を続けたまま Gateway で可視化する、という理解にはならない。

RISK注意点

本番環境を触らせる前に

Caution

Claude Code に本番環境の変更権限を渡す場合は慎重さが必要。DNS や WAF の設定変更は、間違えたときの影響範囲がコードの比ではない。

  • まずは読み取り専用権限で接続する

    ログ確認や設定の点検から始める。書き込みは後から足せる。

  • 変更権限を必要最小限にする

    とくに DNS、WAF、Zero Trust、本番 Worker の変更権限。

  • 「変更前に差分・影響・ロールバック案を出す」と指示する

    プロンプトに書くだけでなく、繰り返すなら CLAUDE.md に、絶対に守らせたいなら フックに。

  • 本番変更は必ず人間が確認する

    ここは自動承認モードにしない。03 の手動モードを維持する場面。

フックで保証に変える

上の3番目は「お願い」なので、モデルが従わないことがある。10 フックの言い方を借りれば——毎回必ず起きてほしいなら、プロンプトではなくフックに入れる。PreToolUse で本番 Worker への書き込みをブロックすれば、権限設定と二重の防御になる。

PATH導入順

安全な導入順

Web 開発で Claude Code を使うなら、Cloudflare はかなり相性が良い。とくにWorkers でアプリを作り、D1 にデータ、R2 にファイルを置き、Claude Code で実装・デプロイ・ログ調査を行う流れが便利。ただし全部を一度に入れる必要はない。

  1. Cloudflare 無料アカウントと wrangler を準備する

    まだ Claude Code は関係しない段階。

  2. Cloudflare Skills プラグインを Claude Code へ導入する

    知識を与えるだけ。何も操作させないのでリスクはない。

  3. OAuth では、最初は閲覧・調査中心の権限で接続する

    認可画面で渡す範囲を絞る。

  4. Workers + D1 の小規模なローカルアプリを作る

    本番に触れずに一通りの流れを体験する。

  5. 「デプロイ前に変更内容を提示し、承認を取る」と毎回守らせる

    依頼文・CLAUDE.md・フックの順に強制力が上がる。

  6. ログ調査や DNS 確認など、MCP の読み取り用途を試す

    ここではじめて MCP を実運用に入れる。

  7. 本番の書き込み操作は、必要になったサービスだけ最小権限で許可する

    「全部開ける」ではなく「必要になったものだけ開ける」。

最初から全権限を渡すより、Skills → 読み取り MCP → 開発用環境へのデプロイ → 本番の順に広げるのが安全。

Cloudflare 自身の推奨

認可範囲に慣れるまでは、デモ用アカウントから始めることが勧められている。
