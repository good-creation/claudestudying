01 — 02 / 土台

何であり、どう動いているか

コードベースを読み、ファイルを編集し、コマンドを実行するエージェント型のコーディングツール。中身は、エージェンティックループ・コンテキストウィンドウ・ツール・権限モードの4つの部品。

03 — 05 / 進め方

主導権を渡さずに走らせる

承認モードとプランモードでどこまで任せるかを自分で決め、探索 → 計画 → コード → コミットの順で進める。コンテキストの残量は /context で見て、/compact と /clear で管理する。

06 — 11 / 積み上げと出荷

同じ説明を、二度としない

毎回の前提は CLAUDE.md へ、調べ物はサブエージェントへ、手順はスキルへ、外部のデータは MCP へ、絶対に守らせたいことはフックへ。最後にレビューを挟んで出荷する。

  1. Claude Code とは何か

    コードベースを理解し、ファイルを編集し、コマンドを実行し、外部ツールに接続するエージェント型のツール。効果的に使うための前提は3つ——コンテキストには限りがある、既定では許可を求める、そして間違えることがある。

  2. どう動いているのか

    プロンプト → コンテキストを集める → アクションを実行する → 結果を検証する、というエージェンティックループ。これにコンテキストウィンドウ・ツール・権限モードが組み合わさる。

  3. 最初のプロンプトを書く

    まず普通に話しかけ、できるだけ具体的に頼む。Shift+Tab で自動承認と手動を切り替え、書かせたくないときはプランモードで計画だけ出させる。

  4. 探索 → 計画 → コード → コミット

    コース中で最も重要なワークフロー。計画は Claude のためだけにあるのではなく、コードが書かれる前に、あなたが軌道修正できる場所を一箇所作るためにある。

  5. コンテキストを管理する

    読んだファイル・ツールの呼び出しとその結果・メッセージが、すべて容量を食う。満杯になると自動で圧縮される。続きをやるなら /compact、話題を変えるなら /clear。

  6. CLAUDE.md ファイル

    プロジェクトのルートに置く、コードベースのオンボーディング資料。セッションのたびに自動で読まれるので、毎回ゼロから説明し直さずに済む。プロジェクトとユーザーの2階層。

  7. サブエージェントとは何か

    専門アシスタントに委譲し、旅路なしで答えを得る。別のコンテキストウィンドウで働くので、15ファイル読んだ途中経過は捨てられ、必要な要約だけがメインに戻る。

  8. スキルとは何か

    同じことを繰り返し説明していると気づいたら、それは書かれるのを待っているスキル。ふだんは名前と description だけが常駐し、依頼にマッチしたときだけ全体が読み込まれる。

  9. MCP で外部につなぐ

    コンテキストの多くはコードベースの外——データベース、業務アプリ、公開リポジトリ——にある。MCP はそこへつなぐオープン標準。ただしツール定義は常時コンテキストを占めるので、入れすぎない。

  10. フックで確実に実行させる

    このコースで唯一の決定論的な手段。毎回必ず起きてほしいことは、プロンプトに書くのではなくフックに入れる。整形やログは PostToolUse、危険な操作の遮断は PreToolUse。

  11. レビューして出荷する

    04 の最後の段を操作に落とす回。偏りのないレビューを読み取り専用のサブエージェントに任せ、/commit-push-pr でコミットから PR までを一手で済ませ、--from-pr で同じ文脈に戻る。
