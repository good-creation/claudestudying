01
What is Git?

Git とは何か

結論は「コードの保管庫」。ただのファイル共有ではなく、誰が・いつ・どこを・どう変えたかが一緒に残る。そして一番大事な考え方——ファイルを見るな、履歴を見ろ。最新版_final_絶対最後.zip をやめる理由がここにある。

  • コードの保管庫
  • 履歴を管理する
  • 悪い例と良い例

02
Commit & main

コミットと main

コミットは変更を1つずつ履歴として残すセーブポイント。まとめて1回ではなく、作業の区切りごとに1つ。その「1つずつ」を成り立たせている git add（ステージングエリア）も補足として置いた。main は「本番の出し物」＝公式の最新版で、壊さない・いつでも動く状態にするという2つの決まりを持つ。

  • セーブポイント
  • git add
  • ステージング
  • main は壊さない

03
Branch & Merge

ブランチとマージ

Branch は枝。main から枝分かれした安全な作業場所で、資料の言い換えは「下書きノートを作成」。枝ごとに別々の作業を同時に進められ、仕上がったものを MERGE で main に統合する。

  • 下書きノート
  • 同時進行
  • 統合する

04
Local, Remote, PUSH & PULL

ローカル・リモートと PUSH / PULL

ローカルは自分だけの場所、リモートはチーム全員の集合場所。PUSH＝アップロード、PULL＝ダウンロード、MERGE＝履歴の統合。そして「なぜ別のパソコンでもマージできるのか」——共有しているのがファイルではなく履歴だから。

  • 空間のルール
  • Action Matrix
  • 履歴を共有する

Conflict

コンフリクト

同じ画面を別々に変更したときに起きる衝突。どちらの変更も正しいので、機械には決められない——決めるのは人。直し方は2手順で、GitHub が箇所を提示し、Claude Code / Codex に修正を頼む。

このコースの用語

各ページの本文でも、点線のついた語にカーソルを合わせる（スマホならタップする）と、やさしい言い換えが出ます。

コミット
変更を1つずつ履歴として残すセーブポイント。資料はこれを「ファイルの保存」と等号で結んでいる。
git add / ステージングエリア
コミットの直前にある待機場所へ、履歴に残したい変更だけを選んで登録する操作。自分のパソコン内で完結し、リモートにはまだ送られない。研修資料には無い補足。
main
プロジェクトの公式の最新版。確認された完成形を置く場所で、壊さず、いつでも動く状態に保つ。
Branch（ブランチ）
main から枝分かれした安全な作業場所。資料の言い換えは「下書きノート」。
MERGE（マージ）
別々の変更を main に統合する操作。移動の方向はブランチから main へ。
ローカル / リモート
ローカルは自分のパソコン＝自分だけが作業する場所。リモート（GitHub）はクラウド上の保管場所＝チーム全員の集合場所。
PUSH（プッシュ）
ローカルで作った変更をリモートに送る操作。アップロードにあたる。
PULL（プル）
リモートの最新変更をローカルに取り込む操作。ダウンロードにあたる。
Conflict（コンフリクト）
同じ画面を別々に変更したときに起きる衝突。どちらを採用するかは人が決める。
プルリクエスト
7ステップの6番目。作った枝を本線に入れたい、という申請にあたる。
