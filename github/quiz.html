レッスン01〜06を、一枚に。

出題範囲はこのコースの全6レッスン。6本を貫いているのは「管理しているのはファイルではなく履歴だ」という一行で、コミットもブランチも PUSH / PULL も、すべてその一行の言い換えとして出てくる。

01 — 02 / 土台

履歴を管理する、という発想

Git は誰が・いつ・どこを・どう変えたかまで残るコードの保管庫。管理の対象はファイルではなく履歴で、その履歴を1つずつ刻む操作がコミット、集まる先が main。

03 — 04 / 場所と操作

枝で分けて、送って、取ってくる

作りかけはBranchで書き、仕上がったら MERGE で本線へ。手元とクラウドのあいだは PUSH（送る）と PULL（取ってくる）で行き来する。

05 — 06 / 運用

衝突は人が決め、本線は最後に動く

同じ場所を2人が触ると Conflict。場所は GitHub が示し、修正は AI に頼める。7つのステップを守れば、本線が書き換わるのは最後の1回だけ。

  1. Git とは何か

    結論は「コードの保管庫」。ただのファイル共有ではなく、誰が・いつ・どこを・どう変えたかが一緒に残る。そして一番大事な考え方がファイルを見るな、履歴を見ろ。

  2. コミットと main

    コミットは変更を1つずつ履歴として残すセーブポイント。main は本番の出し物であり公式の最新版で、壊さない・いつでも動く状態にするという2つの決まりを持つ。

  3. ブランチとマージ

    Branch は main から枝分かれした安全な作業場所＝下書きノート。枝ごとに別々の作業を同時に進められ、MERGE で別々の変更を main に統合する。

  4. ローカル・リモートと PUSH / PULL

    ローカルは自分だけの場所、リモートはチーム全員の集合場所。PUSH＝アップロード、PULL＝ダウンロード、MERGE＝履歴の統合。別の PC でもマージできるのは、共有しているのが履歴だから。

  5. コンフリクト

    同じ画面を別々に変更したときに起きる衝突。どちらを採用するかは人が決める。GitHub が箇所を提示し、Claude Code / Codex に修正を頼む2手順。

  6. 実際の開発フロー

    PULL → ブランチ → 作業 → コミット → PUSH → プルリクエスト → 確認してマージ。この流れを守れば main は絶対に壊れない。
