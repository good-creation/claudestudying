WHY正体

MCP って何のこと？

AI と外のサービスをつなぐときの、共通の決まりごとです。

Model Context Protocol の頭文字。この決まりに従っていれば、Claude Code はいろいろな外のサービスにつながれます。

たとえるなら

USB の差し込み口です。マウスもキーボードも外付けの記憶装置も、形と決まりが同じだから同じ穴に挿せます。ひとつ覚えれば、つなぎ先が変わっても同じやり方が通じます。

確認 MCP を「共通の決まりごと」と呼ぶのは、どういう意味ですか。
  • どのサービスにつないでも、同じ情報が返ってくるということ
  • つなぎ方の形がそろっているので、相手が変わっても同じやり方が通じるということ
  • 接続できるサービスの数が、あらかじめ決められているということ

答え: B — 形と手順がそろっていることが「共通」の意味です。

だから、つなぎ先ごとに別のやり方を覚え直す必要がありません。

EXAMPLE実例

何につなぐと、何ができるのか

プログラムの外にある情報を、持ってこられるようになります。

  • 仕事の管理サービスにつなぐ

    特定の作業項目の中身を取り込めます。「この案件を読んで、計画を立てて」が通ります。

  • 最新の説明書を取ってくるサービスにつなぐ

    いま使っている部品の、最新の説明書を届けてくれます。

つないだ道具も、ふつうの道具と同じで使う前に確認を求めてきます。勝手に外へ問い合わせが飛ぶことはありません。

確認 外につないだ道具を使うとき、確認はどうなりますか。
  • ふつうの道具と同じように、使う前に確認を求めてくる
  • 外への接続なので、確認は必ず省略される
  • 最初の一回だけ確認され、それ以降は自動で通る

答え: A — 特別あつかいはされず、いつもの許可の仕組みが働きます。

知らないうちに外へ問い合わせが飛ぶ、ということにはなりません。

ADDつなぎ方

つなぐ、そして管理する

追加は claude mcp add。相手がどこで動いているかで2種類に分かれます。

  • HTTP — 遠くにあるサービス向け

    相手のサービス側で動いていて、ネットワーク越しにつながります。

  • stdio — 手元で動かすもの向け

    自分のパソコンの中で動いていて、プログラム同士が直接やりとりします。

つないだあとの管理は /mcp。何がつながっているか、動いているか、そして要らないものを切ることができます。

確認 2つのつなぎ方は、何によって分かれていますか。
  • 相手が遠くのサービスか、自分のパソコンの中かのちがい
  • 扱えるデータの量のちがい
  • 接続にかかる料金のちがい

答え: A — つなぐ相手がどこで動いているかで、使うやり方が変わります。

どちらでつないでも、追加に使う命令そのものは同じです。

SCOPE届く範囲

どこまで届かせるか

ここも「誰のためか」で決まります。

  • このプロジェクトだけ — 自分だけ

    いま開いているプロジェクトでのみ使えます。

  • 自分の全部 — 自分だけ

    どのプロジェクトでも使えます。

  • チーム共有 — 関わる人全員

    プロジェクトの側に設定を入れておくと、全員が自動で同じ接続を得ます。

ここまでで、同じ型が4回出てきました

メモ帳、スキル、このあとのフック、そして接続。どれも「プロジェクトに入れておけばチーム全員に配れる」という同じ形です。

確認 チーム全員に同じ接続を行きわたらせたいときは、どうしますか。
  • 各自が自分の設定に、同じ内容を書き写す
  • いちばん詳しい人の設定を、そのつど参照させる
  • プロジェクトの側に設定を入れて、共有できる形にする

答え: C — プロジェクトに入れておけば、関わる人全員に自動で行きわたります。

メモ帳やスキルのときと、まったく同じ配り方です。

COST代償

つなぎっぱなしには、代償がある

つないだサービスは、使っていなくても場所を取り続けます。

なぜ場所を取るのか

呼び出していなくても、道具の説明ぶんがずっと居座るからです。たくさんつなぐと、それだけで机が狭くなります。

対策は単純。/mcp で確認して、使っていないものを切る。つながずに済ませる手も2つあります。

  • 命令で代わりができるなら、そちらを使う

    専用の命令があるなら、そのほうが場所を食いません。常に居座る説明ぶんが増えないからです。

  • スキルに書いておく

    スキルは、ふだんは名前と説明文だけ。命令の使い方をそこに書いておく手です。

確認 つないだサービスが場所を取り続けるのは、どんなときですか。
  • 実際に使ったあと、しばらくのあいだ
  • 接続に失敗しているあいだだけ
  • 使っていないときも、つながっているかぎりずっと

答え: C — 呼び出さなくても、道具の説明ぶんが居座り続けます。

だから、いま要らないものは切っておくのがいちばん効きます。

RECAPまとめ

この回のまとめ

  • 命令でつなぐ
  • 設定ファイルでチームに配る
  • 使っていないものは切る

つなげることと、つなぎっぱなしにしてよいことは別の話。
