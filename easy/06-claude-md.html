WHY動機

毎回ゼロから始めさせないために

メモがないと、Claude は毎回まっさらな状態から始めることになります。

中がどうなっているか調べ直し、使っている部品を確かめ直し、すでにある機能を探し直す。そして、いちばん困るのがこれです。分からない部分は、推測するしかなくなります。

たとえるなら

毎日ちがう新人が来るアルバイト先です。実力はあるのに、毎回ゼロから店のルールを説明することになる。説明をやめる方法はひとつ——紙に書いて貼っておくことです。

確認 メモがない状態でいちばん困るのは、どんなことだと説明されていますか。
  • 分からない部分を推測で埋めるので、意図とずれやすくなること
  • 一度に置いておける量が、そのぶん少なくなること
  • 使える道具の種類が、そのつど変わってしまうこと

答え: A — 調べ直す手間より、推測が入ることのほうが厄介だとされています。

推測が混ざると、正しい方向へ導くのがむずかしくなります。

WHAT正体

正体は、ただのテキストファイル

プロジェクトの入口に置く、ふつうの文章ファイルです。始めるたびに自動で読まれます。

言ってしまえば、CLAUDE.md の中身は、あなたのお願いの文章にくっついて送られている。

— 公式コースでの説明

ここが仕組みのすべてです。書いた分だけ、毎回のお願いが長くなります。長いメモは、読まれないのではなく毎回まるごと持ち歩かされるのです。

ゼロから書く必要はありません。/init と打つと、Claude が中を見て下書きを作ります。

確認 このメモを短く保つべきなのは、なぜですか。
  • 長いと、途中までしか読み込まれないから
  • 長いファイルは、始めるときに時間がかかりすぎるから
  • 書いた分だけ、毎回のお願いが長くなってしまうから

答え: C — 中身は毎回のお願いにくっついて送られます。

読まれないから短くするのではなく、毎回持ち歩くことになるから短くします。

WRITE中身

何を書くのか

書くのは「知らないと推測するしかない事実」だけです。

  • 何で作られているか

    「これは〇〇を使ったアプリ」と1行。

  • よく使う命令

    動かすとき、点検するとき。このプロジェクトでの正しい打ち方。

  • 書き方のきまり

    字下げの幅、名前のつけ方など。

  • このプロジェクトの決めごと

    「この種類のファイルはこのフォルダに置く」など。

これがあると、Claude は最初からそのプロジェクトの流儀で書きます。全体を理解しに行く手間がないぶん、一手目から仕事が良くなります。

確認 メモに書く内容に共通しているのは、どんな性質ですか。
  • あとから変わることがない、決まりきった情報であること
  • プログラムを読めば必ず分かる、基本的な情報であること
  • 知らなければ推測するしかなくなる、そのプロジェクト固有の事実であること

答え: C — 推測を減らすために置くものなので、外からは分からない事実が中心になります。

書き方のきまりや、よく使う命令の打ち方が並ぶのはそのためです。

LEVEL置き場所

みんなのメモか、自分だけのメモか

置き場所は「他の人にも当てはまるか」だけで決まります。

  • プロジェクト用 — チーム全員に共有される

    何で作られているか、よく使う命令、プロジェクトの決めごと。

  • 自分用 — 自分だけ、どのプロジェクトでも効く

    個人的な好み（たとえばコメントの書き方）。

ここを混ぜると、他の人にとって邪魔なルールが、共有のファイルに紛れ込みます。

確認 プロジェクト用と自分用を分ける基準は何ですか。
  • その内容が他の人にも当てはまるかどうか
  • 内容が長いか短いか
  • 書いたのが自分かチームの誰かか

答え: A — みんなに関係する事実か、自分の好みかで置き場所が決まります。

混ぜてしまうと、他のメンバーにとって邪魔なきまりが共有のほうに入り込みます。

TIPS育て方

上手な育て方3つ

いきなり完成させず、必要になったものだけを少しずつ足していきます。

Save it

同じ注意をしていたら、書かせる

同じ直しを毎回お願いしているなら、「そのきまりをメモに書いておいて」と頼みます。次からは知っている状態で始まります。

Reference

長い資料は、場所だけ教える

読ませたい資料があるなら @ とファイルの場所を書きます。中身を丸ごと写さずに、必要なときだけ読ませられます。

Start empty

最初は、あえて作らない

始めたばかりのうちはメモなしで進めます。そうするとどこで毎回つまずくかが見えます。それから書けば、余計なことを書かずに済みます。

確認 最初はあえてメモを作らずに始めるとよいのは、なぜですか。
  • どこで毎回つまずくかが見えてから書けば、余計なことを書かずに済むから
  • 始めたばかりのうちは、メモを読み込む仕組みが働かないから
  • 先に書いておくと、あとから書き換えられなくなるから

答え: A — 必要な情報だけの短いメモにするための進め方です。

つまずく場所が分かってきたところで、下書きを作らせればよい、という順番になります。

RECAPまとめ

この回のまとめ

うまくいかない作業とはかどる作業の差は、たいてい渡してある情報にある。

始め方は一行です。何で作られているか、好み、よく使う命令から書き始めて、少しずつ育てていきます。
