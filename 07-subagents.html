0:03定義

専門アシスタントに委譲する

サブエージェントとは、Claude がタスクを委譲できる専門アシスタントのこと。

— 公式解説 / 00:03

それぞれのサブエージェントは、自分専用の会話コンテキストウィンドウと、あなたが定義したカスタムシステムプロンプトを持って動く。そして終わったとき、メインスレッドに返るのは要約だけ——中間作業はすべて隔離されたまま残る。

0:24効用

なぜコンテキストが
守られるのか

Claude Code とチャットしているとき、あなたはメインのコンテキストウィンドウに文脈を足し続けている。すべてのツール呼び出しと、その結果が、そこに保存される（→ 05 コンテキスト管理）。

Claude がサブエージェントを使うと、そこで別のウィンドウが立ち上がる。サブエージェントが受け取る入力は2つ。

  1. 設定ファイルからのカスタムシステムプロンプト

    そのサブエージェントが何者で、どう振る舞うべきかの定義。

  2. 親エージェントが書いたタスク記述

    あなたの依頼にもとづいて、親が具体的な指示に落としたもの。

あとはサブエージェントが自律的に働く。ファイルを読んでも、編集しても、ツールを使っても、そのどれもがメインの会話には現れない。返るのは要約だけで、サブエージェントの会話全体はそのあと完全に破棄される。

1:13実例

旅路なしで、答えを

例として置かれるのは、不慣れなコードベースで決済システムの仕組みを調べるタスク。知りたいのは「返金を処理しているのはどのサービスか」——それだけ。

事実ひとつ

必要だったのがたった1つの事実だったとしても、探索の全記録はコンテキストに残ってしまう。そこが問題だった、というのがこの例の主張。

トレードオフ

いいことばかりではない。メインのウィンドウは、サブエージェントがどうやって結論に至ったのか、途中で何を発見したのかが見えなくなる。要約に含まれなかったものは、メイン側には存在しない。

1:56組み込み

最初から入っているもの

Claude Code には、すぐ使える組み込みのサブエージェントがいくつかある。

  • general-purpose

    探索と実行の両方が必要な、複数ステップのタスク用。

  • explore

    コードベースの高速な検索用。04 で「プランモードに入らずに探索だけしたいとき」に挙がっていたのがこれ。

  • plan

    プランモード中に使われ、計画を提示する前のコードベース調査と分析を担当する。

つまり、あなたがプランモードを使っていた時点で、すでにサブエージェントは裏で働いていたことになる。

2:23自作

自分のサブエージェントを作る

カスタムシステムプロンプトとツールアクセスを指定して、自分で作ることもできる。実体はYAML フロントマターを持つ Markdown ファイル。

いちばん簡単な始め方は、Claude に生成させること。/agents を実行して Create new agent を選ぶと、いくつかのステップを進むだけで済む。

  • エージェントのスコープを選ぶ
  • 目的を定義する
  • アクセスできるツールを選ぶ
  • 色を選ぶ

Claude が名前・説明・プロンプトを生成する。この説明が、Claude がいつそのサブエージェントを呼び出すべきかの指示にもなる——スキルの description と同じ考え方（→ 08 スキル）。

さらなるカスタマイズ

  • 永続的なメモリ

    会話をまたいでメモリを保持できる。同じプロジェクトで継続的に使う場合にとくに有効。

  • スキルの事前読み込み

    skills キーにスキル名を列挙すると、あらかじめ読み込ませられる。ただしメイン会話でのスキルと違い、ここではスキル全体がコンテキストに読み込まれる点に注意。

レビューに使うときの作法

11 レビューと出荷で出てくるが、コードレビュー用のサブエージェントは読み取り専用ツールに限定する。レビュアーは問題を指摘すべきであって、ファイルを編集すべきではない。設定はリポジトリにチェックインして、チーム全体が同じレビュアーを使えるようにする。

2:35まとめ

まとめ

サブエージェントは作業を焦点の定まった断片に分け、メインのコンテキストウィンドウをきれいに保ち、必要なものだけを持ち帰る。

組み込みを使うにせよ自作するにせよ、長いセッションからより多くを引き出すための実践的な手段だ、というのが締めくくり。
