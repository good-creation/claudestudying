REVIEW段 1

サブエージェントに
レビューさせる

PR をプッシュする前に、サブエージェントを使って変更をレビューするよう Claude に依頼する。理由は 07 で見た性質そのままだ。

サブエージェントは独自のコンテキストウィンドウで実行されるため、新鮮な視点を持っている。セッション中にコードを書いていたメインエージェントのバイアスを引き継ぐことはない。

— 公式コース本文

書いた本人にレビューをさせない、という当たり前の原則が、ここでは「別のコンテキストウィンドウ」という形で機械的に保証されるのが要点。

01 — Read-only

読み取り専用に限定する

コードレビュー用のサブエージェントを作るときは、ツールを読み取り専用に制限する。レビュアーは問題を指摘すべきであって、ファイルを編集すべきではない。

02 — Check it in

設定をリポジトリに入れる

サブエージェントの設定はリポジトリにチェックインし、チーム全体が同じレビュアーを使えるようにする。レビュー基準がコードと一緒に版管理される。

SHIP段 2

/commit-push-pr スキル

/commit-push-pr スキルは、コミット・プッシュ・PR 作成を一つのステップでまとめて処理する。それぞれを手動で行う代わりに、このスキルを実行するだけでいい。

Slack との連携

CLAUDE.md にチャンネルが記載された Slack MCP サーバーが設定されていれば、PR のリンクはチームのチャンネルに自動的に投稿される。06 CLAUDE.md と 09 MCP が、ここで合流する。

RESUME段 3

--from-pr で
セッションに戻る

Claude が gh pr create を通じて PR を作成すると、そのセッションは自動的にその PR にリンクされる。

あとでその PR に戻る必要があるとき——レビューコメントに対応する、失敗したビルドを修正する——次を実行する。

ターミナル

claude --from-pr <PR_NUMBER>

これで中断した箇所からすぐに再開できる。05 で見たとおり、/clear すればコンテキストは消える。--from-pr は、消えたはずの文脈をPR という外部の錨から取り戻す手段にあたる。

RECAPまとめ

まとめ

  • プッシュ前にサブエージェント

    偏りのないコードレビューのために。

  • /commit-push-pr

    コミットから PR までの全フローを一つのステップで。

  • --from-pr

    あとで PR の作業を再開できる。

これらは小さな機能だが、日々のワークフローから多くの手間を取り除いてくれる。

この動画について

指定された動画 youtu.be/RKsADl0ZC3Y は、このレッスンの解説動画ではなく 「Introducing Code Review」という45秒のプロダクト告知でした。ナレーションが一切なく（字幕は音楽記号のみ）、書き起こせる内容はありません。以下は公式の説明文と告知記事から取れる情報です。

Code Review は、すべてのプルリクエストにエージェントのチームを派遣し、ざっと目を通すだけでは見逃すバグを捉える機能。PR が開かれると次が起きる。

  1. 並行してバグを探す

    複数のエージェントが同時に走査する。

  2. 一つずつ検証する

    誤検知（false positive）を除外するために、見つけたものを確認する。

  3. 深刻度でランク付けする

    重要なものから順に提示される。
