パラメトリックメモリと
コンテキスト

原題 Parametric memory & context。多くの人がAIチャットを検索の代替として使っている。これを安全に行うには、LLMがどこから情報を得ているかを理解することが重要だ。LLMが誤った情報を生成する場合、それは通常、欠落した、誤った、または低品質なコンテキストの副作用となる。以下は原文の説明部分を日本語で再構成したもの。

MEMORY導入

回答はどこから来るのか

なぜそれが起こるのかを知らなければ、モデルが情報をでっち上げてあなたを欺こうとしていると感じやすくなる。しかし、モデルの知識がどこから来るのかを理解すれば、モデルがどこで間違いを犯す可能性があるかをより明確に予測できるようになる。

原文のインタラクティブ要素 — Quick check

AIチャットモデルがあなたの質問に答えるとき、その回答はどこから来るのか、という4択のクイズが原文冒頭にある。選択肢は「毎回ウェブで調べる」「訓練中に記憶していた」「会話の中にある内容を読む」「質問によって異なる組み合わせ」。

3つすべてが起こる。このレッスンではその順序で説明していく——訓練から得た知識、会話に入力した内容、そしてモデルが自ら調べる内容。

パラメトリックメモリ

モデルは時に、ただ…物事を知っている。この組み込まれた知識はパラメトリックメモリと呼ばれる。なぜなら、それはモデルの重み、すなわちパラメータに焼き込まれているからだ。誰も百科事典を作ろうとしたわけではないが、LLMが記憶から暗唱できる事実は、テキストを予測することを学習した副作用として生まれた。

原文のインタラクティブ要素 — Token prediction

分野を選び（history / science / cinema / programming / policy / creative）、モデルが次の数語を生成するのをクリックで表示し、正しい情報かどうかを自分で判断するウィジェット。例として Who was the first president of the United States? → The first president of the United States of America was … のような続きが示される。

確認 モデルの回答が来る場所として、本文が挙げているのはどれか。
  • 会話の中身だけ
  • 常にウェブ検索だけ
  • 訓練から得た知識・会話に入力した内容・モデルが自ら調べる内容の組み合わせ

答え: C — 本文は「3つすべてが起こる」と述べ、訓練から得た知識、会話に入力した内容、モデルが自ら調べる内容の順に説明していく構成になっている。

訓練から得た組み込みの知識は「パラメトリックメモリ」と呼ばれる。

CONTEXT補う

コンテキストの追加

Claudeが訓練だけでは答えられない質問がある。追加のコンテキストを提供して質問を調整すると、モデルにとってタスクが明らかに簡単になる。

原文のインタラクティブ要素 — Predict the reply

Without context / Contrived context / Authentic context の3条件で、What's the guest wifi password at our Lakeside office? にモデルが正しく答えられるかを予測するウィジェット。

モデルが必要とする可能性のあるすべてを与えるアプローチはコンテキストスタッフィングと呼ばれる。コンテキストスタッフィングは一般的にうまくいくが、いくつかの制約に直面する。

確認 「コンテキストスタッフィング」とは何か。
  • コンテキストウィンドウを空にする操作
  • 使いそうな情報をあらかじめ全部渡しておくやり方
  • 古い会話を自動で削除する仕組み

答え: B — モデルが必要とする可能性のあるものをすべて与えるアプローチをコンテキストスタッフィングと呼ぶ。

一般的にはうまくいくが、コンテキストウィンドウという制約に直面する。

WINDOW上限

コンテキストウィンドウ

言語モデルのコンテキストには最大サイズがある。本稿執筆時点で、現在のフラッグシップClaudeモデルは最大100万トークンを保持できる。これは白鯨（Moby Dick）約3冊分に相当する。

では、どうして誰もが容量不足に陥るのか。AIチャットの初期の頃、制限に達することは最初からやり直すことを意味していた。2024年や2025年にチャットインターフェースでこの制限に自分自身が達したことがあるかもしれない。それでも、それが起こったとき、あなたは小説3冊分よりもはるかに少ない量しか書いていないことを知っている。ほとんどの人はそれほどおしゃべりではない。では、あなたの100万トークンはどこへ行ったのか。

原文のインタラクティブ要素 — ウィンドウを埋める

1,000トークンというはるかに小さいコンテキストウィンドウを持つモデルを想定し、通常のチャットのやり取りでウィンドウが埋まっていく様子を見るウィジェット。初期状態は system prompt + preloaded context = 345 tokens（345/1,000、655 free）。

確認 本稿執筆時点で、現在のフラッグシップClaudeモデルのコンテキストウィンドウの最大サイズはどれくらいか。
  • 約1,000トークン
  • 約100万トークン
  • 約10万トークン

答え: B — 現在のフラッグシップClaudeモデルは最大100万トークンを保持でき、これは白鯨（Moby Dick）約3冊分に相当する。

1,000トークンは、本文が説明のために使っている、はるかに小さい想定モデルの例。

COMPACT要約で続ける

コンパクション

コンパクション：コンテキストウィンドウが限界に近づくと、アプリはClaudeにこれまでの会話全体を要約するよう依頼し、その要約がそれまでのコンテキストを置き換える。コンパクションにより、新しい会話を始める代わりに会話を続けることができる。

  1. ① まず、アプリが気づく

    コンテキストウィンドウに過負荷をかける可能性のあるリクエストを送信する代わりに、アプリはあなたの次のターンを保留し、コンパクションを開始する。

  2. ② 次に、Claudeが要約する

    これまでの会話は、「添付されているのは人間とモデルの間の会話です。これまでに起こったことすべての要約を作成してください」といったプロンプトとともにClaudeに渡される。

  3. ③ 最後に、会話はその要約から続く

    要約が会話履歴を置き換え、その後、①で保留されていたあなたのクエリが応答のためにClaudeに渡される。

原文のインタラクティブ要素 — 試してみる: コンパクション

同じ1,000トークンのウィンドウが埋まっていく実例（トマト栽培の相談）が示される。

1,000トークンウィンドウの内訳（トマト栽培の相談） 
system prompt + preloaded context   345
you（ユーザーの発言 合計）            80
Claude（応答 合計）                 251
tool call                            12
tool result                         184
--------------------------------------
合計                        872 / 1,000（full、128 free）

Claude's calendar reply needs about 140 tokens, but only 128 remain. The context window is full.

コンパクションはどれほどうまく機能するのか

初期のコンパクション実装は明らかに情報が失われやすく、要約の前に与えられた指示が要約を経て残っていないことが分かる場合があった。コンパクションのプロンプトとモデルはその後どちらも改善されたが、それでも要約であることに変わりはない。

Claude Code 入門コースとの関連（推測）

コンパクションが指すしくみは、本サイト Claude Code 入門コースの05 コンテキストを管理するで扱われている内容と同じものを指していると考えられる。以下は原文が明示した対応ではなく、こちらの推測による対応づけ。

確認 コンパクションが起きる順序として正しいのはどれか。
  • アプリが気づく → Claudeが要約する → 要約から会話を続ける
  • Claudeが要約する → アプリが気づく → 保留していたクエリを渡す
  • ユーザーが要約を依頼する → アプリが承認する → 会話が終了する

答え: A — まずアプリがウィンドウの限界に気づいて次のターンを保留し、次にClaudeがこれまでの会話を要約し、最後にその要約から会話が続く。

保留されていたユーザーのクエリは、要約が会話履歴を置き換えたあとでClaudeに渡される。

WRITE書き込み

書き込みメモリ

メモリとは、厳密に制限されたウィンドウが無限に感じられる仕組みだ。Claudeはある会話でメモを書き、そのメモは次の会話の開始時に再び追加される。

メモリを、Claudeがメメントのように物事を書き留め、後でそれを読み返すものと考えるとよい。Claudeは昼寝の後にすっかりリフレッシュして目覚め、以前自分自身のために書いたメモリファイルを見回すことができる。これをパラメトリックメモリと混同しないように、書き込みメモリと呼ぶことにする。

  • コンパクション

    Claudeが単一の会話をコンテキストの限界を超えて続けられる仕組み。

  • 書き込みメモリ

    Claudeが複数の会話にわたって重要な詳細をコンテキストに保持する仕組み。

原文のインタラクティブ要素 — 書き込みメモリの例

火曜日の会話：「Keep updates to my team short and bulleted, please.」→ Claude「Done. That sounds like a standing preference, so I'm writing it down.」→ memory file に "Prefers short, bulleted team updates." を保存。木曜日の会話（新しいセッション）：memory file がコンテキストに静かに挿入される → 「Email this week's update to my team.」→「Sent - short and bulleted, the way you like it.」そのメモリは、火曜日の完全なコンテキストがない全く新しいセッションであっても、将来の会話に引き継がれる。

Claudeの各製品はメモリを異なる方法で実装している。Claude Codeはコードベース全体の CLAUDE.md ファイルを読み込むが、claude.ai は設定内にメモリを保持する。しかし、場所が異なっていても、プロセスは同じだ。Claudeは重要な情報を書き留め、後のインスタンスのClaudeが次の会話の開始時にそれを読み返す。

Claude Code 入門コースとの関連（推測）

ここで言う CLAUDE.md への書き込みメモリは、本サイト Claude Code 入門コースの06 CLAUDE.md ファイルで扱われている内容と同じ仕組みを指していると考えられる。以下は原文が明示した対応ではなく、こちらの推測による対応づけ。

原文のインタラクティブ要素 — メモリの1週間

同じアシスタントと過ごす5日間（Mon 1 line → Tue 2 → Wed 2 → Thu 3 → Fri 3）。月曜の例：「I'm coordinating the November leadership summit - about 250 people, working back from a Nov 12 date.」→ memory file に - Coordinating the November leadership summit (~250 attendees, working back from Nov 12) を追記。

何を覚えておく価値があるのか。あなたのプロジェクト、好み、仕事上の関係は残されたが、出欠確認の人数やケータリングの見積もりといった、より一時的で細かい詳細は残されなかった。Claudeは、それらを書き留めて変わっていないことを期待するのではなく、次にそれらが話題になったときに調べることができるし、そうすべきだ。

確認 コンパクションと書き込みメモリの違いは何か。
  • 両者はまったく同じ仕組みで、呼び方が違うだけ
  • コンパクションは単一の会話をウィンドウの限界を超えて続ける仕組みで、書き込みメモリは複数の会話にわたって重要な詳細を保持する仕組み
  • コンパクションは複数の会話にわたって記憶を保持し、書き込みメモリは単一の会話を続ける仕組み

答え: B — コンパクションは単一の会話をコンテキストの限界を超えて続けられる仕組み、書き込みメモリは複数の会話にわたって重要な詳細をコンテキストに保持する仕組み。

混同を避けるため、モデルの重みに焼き込まれたパラメトリックメモリとも区別して「書き込みメモリ」と呼んでいる。

AGENTIC自ら調べる

前置きされたコンテキスト

視野を広げると、Claudeがあなたの最初のトークンを目にする前に、非常に多くのものがコンテキストに追加されている。Coworkのようなツールでは、Claudeとの会話に追加される可能性のある前置きコンテキストは約19,000トークン。

System Prompt — 約9,000トークン（written by Anthropic）

Instructions that define Claude's role, tone, and guardrails inside Cowork.
"You are Claude, operating inside a product called Cowork. Your goal is to help the user accomplish work tasks. You have access to the user's connected tools, memory, and skills. When the user asks you to take an action, prefer using a tool over describing what you would do …"

原文の断り書き

これは、あなたの最初のメッセージが届く前にClaudeが目にするものを示す例示的なモックアップ。この図の内容とトークン数は代表例であり、特定のClaude製品の現在の状態をバイト単位で正確に表すものではない。

実物を読んでみたいか。Anthropicは、Claudeアプリのシステムプロンプトを公開しており、モデルが変わるたびに更新している。それを読むことは、製品の動作のどれだけがモデルに訓練されているのではなくプロンプトに書き込まれているかを知る素晴らしい方法だ。

エージェント的コンテキスト

エージェント的コンテキストとは、Claudeが回答する前により多くのコンテキストを取得することを決定する場合だ。トマトの植物の例では、Claudeはパラメトリックメモリやすでに持っているコンテキストから回答するのではなく、検索ツールを使用した。

原文のインタラクティブ要素 — "You are the model"

あなたがClaudeで、サイドバーがあなたのコンテキスト。各プロンプトについて、Answer directly（すでに知っていることから答える）かCall a tool（自分の外に手を伸ばす）かを決める。利用できるツールとして web_search（Search the web and return result snippets.）、calendar_list_events（List events on the user's calendar.）、messages_read（Read recent messages from a team channel.）が示され、例題として What's on my calendar tomorrow? が挙げられている。

原文のインタラクティブ要素 — コンテキストをたどる

Coworkの返信例の中でハイライトされた6つの語句が、前置きされたコンテキストのどこから来たかを当てるウィジェット。

Short version: the venue walkthrough is Thursday at 2:00 pm (Pacific), and Dana has already accepted.
I can email the team to say you'll be joining remotely - I'd copy Dana, since she gets your Friday recaps, unless you'd rather choose the recipients yourself. Want me to go ahead?

Cowork · replying to: "When's the venue walkthrough for the summit? And can you let the team know I'll be joining remotely?"

KEYまとめ

今できるようになったこと

  • 重みの中にあるもの（パラメトリックメモリ）とウィンドウの中にあるもの（コンテキスト）の違いを名指しできる

  • ウィンドウには上限があり、それを埋めているのはあなただけではないことを知っている

  • コンパクションが、ウィンドウを無限に感じさせることができる要約技術であるが、詳細を失う可能性があることを理解している

  • 書き込みメモリがセッション間でどのように存続するかを説明できる

  • Claudeの返信を見て、前置きされたコンテキストがそれをどのように形作った可能性があるかについて推測できる
