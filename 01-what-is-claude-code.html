0:00定義

Claude Code とは何か

まず押さえたい定義は、Claude Code がエージェント型のコーディングツールであること。あなたのコードベースを理解し、ファイルを編集し、コマンドを実行し、既存の開発ツールと統合して、作業をより速く終わらせる。

この一文に、後半で展開される要素がすべて畳み込まれている。「理解する」「編集する」「実行する」「統合する」——単にコードを書いて返すのではなく、環境の中で動くことが前提になっている。

動作環境として挙げられるのは次の5つ。

  • Terminal
  • Visual Studio Code
  • Claude Desktop App
  • Web
  • JetBrains IDEs

以降の説明は、ターミナルでの利用を前提としている。

AI エージェント

一番分かりやすい違いは、Claude Code がAI エージェントとして動くこと。コピペの往復がなくなるのは結果であって、原因はこのアーキテクチャの違いにある。

1:00概念

AI エージェントとは

環境と相互作用し、定義された目標を達成するためにアクションを実行できるソフトウェア。

— 公式解説の定義 / 01:02

そして、その核心は大規模言語モデルがリアルタイムでループ動作することだと説明される。一問一答ではなく、判断と実行と観測を回し続ける構造のことだ。この「ループ」がコース2本目の主題になる。

さらにエージェントは、目標達成を助けるためにツール・外部サービス・他の AI エージェントにアクセスできる場合がある、と補足される。Claude Code が「ファイル編集」「コマンド実行」「Web 検索」を持っているのは、この一般論の具体化にあたる。

1:20実例

実際に何ができるのか

抽象的な定義のあと、具体例が挙げられる。数は絞られているが、それぞれが別の能力軸を代表している。

  • コードベースを読み取り、理解する

    「この機能を説明して」「このバグをコード全体にわたって追跡して」と頼める。読解と横断的な調査。

  • プロジェクト全体のファイルを編集するコース本文のみ

    関数をリファクタリングし、それを参照しているすべてのファイルを合わせて更新できる。1ファイル単位ではなく、変更の波及範囲までを担当するということ。

  • ターミナルコマンドを実行する

    ビルドスクリプトの実行、テストの実行、パッケージのインストール。重要なのは「実行して終わり」ではない点で、use the output to decide what to do next（出力を使って次に何をすべきかを判断する）。ここがループの実体にあたる。

  • Web を検索する

    ドキュメントや最新の API リファレンスが必要になれば、自分で調べに行く。学習データのカットオフを外部で埋める動き。

1:45前提

効果的に使うための
3つの前提

実務上いちばん重要なのがこのパート。「Claude Code を効果的に使うには、次の3つの概念を念頭に置いてほしい」として並べられる。

Context window

コンテキストウィンドウ

Claude の作業メモリ。多くを保持できるが、一度にすべては保持できない。ここで「エージェント的」な側面が発揮される——コードベース全体をコンテキストに読み込むことなく、戦略的な方法で答えを見つけ出す。

Permission

許可を求める

デフォルトでは、コマンドを実行したり変更を加えたりする前に必ず確認を求める。積極的に関与するやり方でも、あまり関与しないやり方でも、常にあなたが主導権を持っている。

Caution — it makes mistakes

間違いを起こすことがある

他のツールと同様に、Claude Code も完璧ではない。

  • あなたの意図を誤解する
  • 新しいバグを導入する
  • 解決策を過剰に複雑化させる

状況を把握し続けることで、これらを早期に発見できる。

2:25まとめ

まとめ

Claude Code はエージェント型のコーディングツール。コードベースを読み取り、ファイルを編集し、コマンドを実行し、外部ツールに接続することで、より速く成果を出すのを助ける。

Claude Code は、ターミナル、VS Code、JetBrains、Claude デスクトップアプリで使用できる。

この回は概念の導入に徹していて、インストール手順や具体的なコマンドは出てこない。「エージェントとして動く」の中身——ループ・コンテキスト・ツール・権限——は、次の 02 Claude Code はどう動いているのか で分解される。
